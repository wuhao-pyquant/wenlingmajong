# 光子登录与选桌大厅设计

日期：2026-07-10

状态：设计已确认，等待书面审阅

## 背景

当前线上入口由两个静态页面组成：

- `/battle-login` 提供账号登录和邀请码注册。
- `/battle-lobby` 提供账号状态、管理员入口、新房间 AI 设置和最多三张房间桌位。

功能已经可用，但视觉仍接近后台工具页。登录和注册并排展示，选桌页主要依赖普通卡片，缺少成熟产品的空间层次、动态反馈和品牌感。

本设计只改造登录、注册和选桌大厅。对战页面 `/battle`、`battle.html`、`battle_app.js`、`battle_geometry_v7.css` 以及牌局服务端逻辑不在改动范围内。

## 已确认方向

视觉和交互采用用户确认的组合：

- D「光子中枢」：深黑空间、青白粒子网络、锐利动态光束。
- G「无缝舞台」：登录控制条与大厅在同一套视觉舞台中连续展开。
- K「展示级动态」：中高密度粒子、双光束、悬浮麻将牌和完整大厅转场，并按设备性能降级。
- Three.js 主场景：真实三维麻将牌、粒子与灯光。
- Canvas 2D 降级：WebGL 2 不可用、加载失败、上下文丢失或设备性能不足时使用。

## 目标

- 将登录、注册和选桌大厅升级为现代科技公司展示级界面。
- 保留现有账号、邀请码、角色、管理员、房间、座位、准备和 AI 功能。
- 允许重新组织前端元素，但不改变接口地址和服务端行为。
- 让桌面端和手机端都保持清晰、可操作和无横向溢出。
- 将三维和粒子计算限制在访问者设备，避免增加 NAS 的牌局计算负载。
- Three.js 只在登录页和选桌大厅加载，确保对战页面不下载、不初始化也不运行相关代码。

## 非目标

- 不修改对战页面视觉、布局、动画或交互。
- 不修改麻将规则、房间服务、登录接口、注册接口或权限模型。
- 不把登录大厅改造成单页应用。
- 不引入前端构建系统、React、Vue 或新的后端框架。
- 不依赖国外 CDN、远程字体或运行时外部资源。
- 不在 WebGL 中绘制输入框、按钮或房间文字。

## 页面隔离

`battle_login.html` 和 `battle_lobby.html` 使用独立页面类：

- 登录页：`.photon-auth-page`
- 大厅页：`.photon-lobby-page`

新 CSS 不使用裸 `.button`、`.card`、`canvas` 等全局选择器。新脚本只由这两个 HTML 页面引用。

测试必须明确断言：

- 登录页包含 `photon_scene.js`。
- 大厅页包含 `photon_scene.js`。
- 对战页不包含 `photon_scene.js`、Three.js 路径或光子页面类。
- `battle_app.js` 不导入、不调用 `WenlingPhotonScene`。

## 场景架构

### Three.js 层

三维画布固定为页面背景：

- 全屏透明 WebGL 画布。
- `PerspectiveCamera` 提供轻微景深。
- `Points` 形成粒子网络。
- `LineSegments` 只连接距离较近的粒子，连接数量受质量档位限制。
- 三张简化麻将牌使用低面数几何体、标准材质和运行时 Canvas 字纹理。
- 环境光、方向光和两个移动点光形成 K 档双光束效果。
- 第一版不使用复杂后期处理链；辉光主要通过发光材质、点精灵和 CSS 光束完成。

Three.js 画布设置 `pointer-events: none`。所有可点击和可输入元素保持为普通 DOM，位于画布上方。

### 页面接口

`window.WenlingPhotonScene` 只暴露：

- `playAuthSuccess()`：播放登录或注册成功转场，返回一个有最大等待时间的 Promise。
- `playLobbyReveal()`：播放房间大厅展开动画。
- `notifyRoomChanges(changes)`：只为发生变化的房间和座位播放反馈。
- `setStatus(kind)`：将 `loading`、`success` 和 `error` 映射为克制的场景颜色反馈，不改变业务文本。
- `destroy()`：停止循环并释放所有资源。

页面功能不得依赖这些方法存在。每次调用都使用可选调用和超时保护，场景失败时立即执行正常业务流程。

## 登录与注册设计

### 布局

- 页面全屏显示光子场、三张悬浮麻将牌和品牌标题。
- 顶部左侧显示温岭麻将品牌，右侧显示系统在线状态。
- 底部为固定操作控制条，不再同时显示两个表单卡片。
- 控制条提供“登录”和“邀请码注册”分段切换。

### 登录模式

保留：

- `loginAccountInput`
- `loginPasswordInput`
- `loginBtn`

密码栏继续显示“推荐密码1234”。回车提交和 `autocomplete` 行为保留。

### 注册模式

切换后控制条平滑展开并显示：

- `registerAccountInput`
- `registerPasswordInput`
- `inviteCodeInput`
- `registerBtn`

邀请码继续默认填入 `WL1234`，输入类型保持 `password`，页面显示为遮挡字符。系统仍只接受密码 `1234`。

### 状态和转场

- `authStatusTitle`、`authStatusDetail` 和 `lobbyMessage` 保留。
- 状态区域嵌入控制条上方，更新时不改变整体尺寸。
- 登录或注册成功后调用 `playAuthSuccess()`。
- 动画最多等待 700 毫秒，超时或失败时立即导航到 `/battle-lobby`。
- 导航前在 `sessionStorage` 写入一次性转场标记；大厅读取后从对应视觉状态继续展开。
- 开启减少动态效果时不等待动画，直接导航。

### 手机端

- 控制条变为屏幕底部全宽面板。
- 面板在软键盘出现时保持当前输入可见，不使用固定像素高度。
- 标题和三维麻将牌缩小并向上移动。
- 注册模式允许面板内部滚动，但页面不产生横向滚动。

## 选桌大厅设计

### 顶部工具栏

保留并重新排列：

- `currentAccountLabel`
- `currentRoleLabel`
- `adminEntry`
- `logoutBtn`
- `roomAiPolicySelect`
- `lobbyMessage`

管理员入口只对管理员显示。退出按钮在桌面和手机端始终可见。

“新房间 AI”在视觉上使用低级/高级分段控制，但底层仍同步到原有 `select` 值，避免改变创建房间请求格式。

### 房间网络

`roomTableGrid` 继续固定包含三个槽位。每个房间模块显示：

- 房间名称和状态。
- 房主。
- 房间统一 AI 等级。
- 东、南、西、北四个座位。
- 玩家名、空座、准备和当前账号状态。
- 创建、加入、进入或准备操作。

房间模块使用 `article`，不再把“准备”按钮嵌套在另一个按钮中。创建、加入和进入按钮使用 `data-slot-index`，准备按钮使用 `data-room-id`。

业务行为保持：

- 空房间调用现有创建流程。
- 已有未开始房间调用现有自动落座流程。
- 已在房间中的玩家直接进入。
- 对局中且未入座的玩家不能加入。
- 满座且未入座的玩家不能加入。
- 准备按钮调用现有 `toggleReady()`。

### 增量动画

- 三秒房间轮询频率不变。
- `renderTableSlots()` 在渲染前比较标准化房间摘要。
- 只将变化列表传给 `notifyRoomChanges()`。
- 空闲房间使用灰白信号，等待使用青绿，对局中使用琥珀，异常和关闭使用红色。
- 当前账号所在房间保持弱光描边，不持续播放强动画。
- 轮询更新不重新播放整页大厅展开动画。

### 手机端

- 三个房间模块纵向排列。
- 顶部工具栏压缩为两行，不隐藏管理员或退出入口。
- 房间桌位使用稳定纵横比，座位标签不能改变模块尺寸。
- 所有主要操作至少保留触控友好的点击区域。
- 页面允许纵向滚动，不允许横向溢出。

## 性能策略

### 质量档位

初始化使用展示级中档，然后根据屏幕和实测帧时间调整：

- 桌面展示档：最多 220 个粒子、1100 条邻近连接、两盏移动点光、三张 3D 麻将牌，像素比最高 1.5。
- 手机展示档：最多 110 个粒子、420 条邻近连接、一盏移动点光和一盏静态光，像素比最高 1.2。
- Three.js 低档：最多 60 个粒子、160 条邻近连接、一盏静态光，像素比最高 1.0。
- Canvas 2D 降级档：桌面最多 60 个粒子，手机最多 36 个粒子，像素比固定为 1.0。
- 静态档：不运行 Three.js 或 Canvas 动画，仅显示 CSS 静态深色背景。

场景启动后采样前两秒可见帧的平均耗时。平均帧耗时超过 24 毫秒时降一个 Three.js 档位；降档后再采样两秒，平均帧耗时仍超过 32 毫秒时切换到 Canvas 2D。质量在同一页面会话中只降不升，避免来回跳动。

### 生命周期

- `visibilitychange` 为隐藏时停止动画循环，恢复后继续。
- `pagehide`、`beforeunload` 和显式导航前调用 `destroy()`。
- `destroy()` 必须：
  - 清除 `setAnimationLoop`。
  - 移除监听器和 `ResizeObserver`。
  - 释放几何体、材质、纹理和渲染器。
  - 移除画布。
- WebGL 上下文丢失时停止 Three.js，并启动 Canvas 2D 降级。

### NAS 资源边界

NAS 只提供额外的本地 JS、CSS 和许可证静态文件。粒子、三维牌和灯光均在访问者浏览器执行。

不增加：

- 牌局计算。
- 房间轮询频率。
- SQLite 写入。
- `wenling-cloudflared` 的计算职责。

增加的主要成本是首次下载静态文件和少量带宽；浏览器缓存后不会在每次轮询重复下载。

## 降级和错误处理

降级顺序：

1. Three.js 展示级场景。
2. Three.js 低质量场景。
3. Canvas 2D 粒子背景。
4. CSS 静态深色背景。

触发条件：

- 不支持 WebGL 2。
- Three.js 动态导入失败。
- 创建渲染器失败。
- WebGL 上下文丢失。
- 初始帧时间持续过高。
- 用户开启减少动态效果时直接进入静态档，不运行 Three.js 或 Canvas 动画。

场景错误只写入控制台并切换降级层，不覆盖登录、注册或大厅业务错误。

业务错误处理保持：

- 登录和注册错误显示在认证状态区域。
- 房间接口失败保留最后一次房间内容，并显示 `lobbyMessage`。
- 401 继续清除会话并返回登录页。
- 场景 API 超时不阻止页面导航或房间操作。

## 数据流

### 登录

1. 页面立即渲染 DOM。
2. `photon_scene.js` 在后台选择 Three.js 或降级层。
3. 用户提交现有 `/api/auth/login`。
4. 成功后保存现有本地会话。
5. 播放最多 700 毫秒的成功转场。
6. 导航到 `/battle-lobby`。

### 注册

1. 用户切换到注册模式。
2. 页面展示现有注册字段和默认遮挡邀请码。
3. 提交现有 `/api/auth/register`。
4. 成功后保存现有本地会话并执行与登录相同的转场。

### 大厅

1. 页面验证现有 token。
2. 调用现有 `/api/lobby/rooms`。
3. 生成三个房间模块。
4. 若存在一次性转场标记，播放大厅展开动画并删除标记。
5. 每三秒继续现有轮询。
6. 只把变化房间传给场景反馈。
7. 创建、加入和准备仍调用现有接口。
8. 进入 `/battle?room_id=...` 前销毁场景。
